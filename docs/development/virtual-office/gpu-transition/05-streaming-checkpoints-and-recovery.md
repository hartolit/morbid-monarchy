# 05 — Streaming, complete checkpoints and recovery

Execute after 04. Replace CPU-grid extraction and retained active payloads with generation-safe
GPU residency and versioned storage. Deliver real restart and failure handling, not just a serializer
or a successful save log. All exercises use temporary stores and preserved legacy copies.

## Read and scope

Read the handoff, acceptance A08/A09, world-format and GPU contracts, implementation/GPU practices
and the actual legacy chunk manager, save/load tasks and redb adapter. The CPU can generate/load
incoming chunks; once resident, their live payload belongs to the GPU. Reuse runtime ports and
transfer reservations rather than introducing a second worker or staging framework.

## Checkpoint A — Residency without CPU authority

Implement absolute-key residency records, per-request/slot generations, dirty/captured/durable
revision tracking and bounded loading/generation. Differentiate absent, corrupt, unsupported and
I/O-failed reads. Only genuine absence authorizes deterministic generation. Handle cancelled/stale
loads without applying them to a recycled slot or clearing a newer request's state.

Implement upload reservation, activation and dependency waking. Validate the actual axis/scale
mapping from 01, negative keys, corner crossings and closed missing-neighbour boundaries. Apply 04's
body edge policy, including suspension/pinning and correct reconstruction without duplicate bodies.
Unloaded regions remain frozen; no implied catch-up engine is introduced.

Capture outgoing dirty data into independent storage before slot reuse. The captured source must
survive delayed CPU mapping and failed disk writes. Reload resolves the newest retained revision
before any stale disk payload. An older asynchronous save cannot overwrite a newer state. Track
snapshot obligations by bytes and identity, not only task count.

Implement successful and refused resize while simulation, captures and loads are in flight. Reserve
old/new overlap and retain the valid old world on a preflight refusal. Keep normal application
progress nonblocking; pressure may visibly stop residency expansion rather than overwrite dirty
state. Remove permanent active chunk cell arrays from the new runtime.

## Checkpoint B — One consistent checkpoint

Implement a versioned world header, immutable chunk/body revisions and atomic manifest publication
using the world-format contract. Specify exact serialization bytes, lengths, integrity checks,
physical configuration/rule identity and compatibility policy. Validate untrusted lengths before
allocation; GPU struct padding and transient handles are never the save format.

A complete checkpoint captures resident dirty chunks, body/suspended state and required configuration
at a completed logical tick. Reserve an independent GPU image, order capture at that boundary and
stream it through bounded CPU payload slots. An equivalent proven snapshot scheme needs recorded
reason and evidence. Reading unrelated changing ticks into one manifest is not a checkpoint.

Include previously inactive immutable revisions without pretending they continued simulating.
Write payloads in bounded transactions; publish the new manifest only after every reference is
successfully durable under the selected redb setting. Test crash points around preparation and
publication: reopening must select the previous complete or new complete checkpoint, never partial
state. Reclaim unreachable prepared data only after proving reachability and respecting live work.

Make autosave and explicit save use this same owner. A save receipt distinguishes requested,
captured, committed and failed. Failed writes retain retryable payload/source; logging and dropping
it is forbidden. Backpressure bounds memory even during repeated failure.

## Checkpoint C — Import, shutdown and recovery consumers

Implement and document actual parser options for selecting a store, saving/reopening and importing
legacy data. Use fixtures captured by the old writer, not bytes generated by the new reader.
Read originals without destructive migration; write a separate new store and report the supplied
interpretation of missing seed/scale metadata. Preserve unsupported or corrupt originals and fail
explicitly. Test interrupted import and destination failure.

Implement orderly close: stop admission, choose a completed boundary, capture required dirty live
state, finish/join queued and in-flight work, publish the checkpoint and report an honest result.
A bounded timeout/failure is visible; it cannot announce safe saving of uncaptured resident changes.

Implement recovery from the latest complete checkpoint with a new session epoch. Controlled device
loss invalidates old handles and callbacks. Show the acknowledged possible loss since the last
checkpoint; do not invent recovery of unsnapshotted GPU state or a durable command journal. Test
loss after capture but before readback according to the retained data actually available.

## Checkpoint D — Fault and end-to-end evidence

Register and execute the `streaming` GPU suite together with real temporary-store tests. Cover
out-of-order loads, stale/reused slots, older saves finishing later, failures before/during commit,
full staging/retry budgets, snapshot plus resize overlap, corrupt/truncated/future-format rows,
resident-only autosave, body suspension/resume, periodic save and orderly shutdown.

Use injected I/O errors at the storage boundary plus actual reopen/recovery tests; a mock that always
returns success cannot establish durability. Include process interruption at defined test barriers
where supported, and distinguish it from a simulated returned error. Prove a deliberate stale-save
specimen is rejected. Keep required tests non-destructive and runnable without external services.

Extend `resident-world`: leave edited chunks, return while a save is delayed, then finish a complete
checkpoint, destroy runtime/store objects and reopen. Compare promised cell/body/configuration state
and revisions. Measure transfer bytes, retained/retry peak memory, queue age and save/streaming frame
impact. Run ordinary resident simulation separately to prove it still has no recurring world readback.

## Acceptance and stop

A08/A09 are complete: metadata-only normal residency; safe generation/slot/revision handling; bounded
snapshots; complete atomically published checkpoints; real failed-save retention, import and recovery.
The GPU/CPU consumers use one lifecycle. Update maintained format/operations recipes, status and
handoff with actual commands and evidence. Commit coherent checkpoints and stop before 06.

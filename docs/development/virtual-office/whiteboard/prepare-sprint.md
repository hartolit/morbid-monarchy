# Prepare another sprint

Read the repository entry point and whiteboard overview, then select only topics relevant to the
requested outcome. Recheck their source/evidence against the current revision. Do not assume an
older benchmark or an earlier agent's preferred design is still valid.

For each selected responsibility, identify the actual operation to improve, current owner,
independent acceptance, necessary upstream decisions and stop condition. Consider retaining the
current implementation or making a smaller correction. Put broad uncertain choices before their
dependent implementation, but do not add a planning phase merely to repeat settled intent.

Produce a finite sequential program with a first adoption prompt, complete implementation
assignments and final integrated evidence. Include local tests where each interface becomes a
dependency; schedule expensive system-wide qualification deliberately. Record temporary bridges
and the stage that removes them. Do not copy the previous sprint's metrics or case names without
checking whether they still test the requested result.

Update only topics actually investigated. Stop at the requested planning deliverable; preparing a
sprint is not authorization to execute it.
